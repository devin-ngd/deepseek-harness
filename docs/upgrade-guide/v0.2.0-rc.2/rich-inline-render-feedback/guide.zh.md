# 同步升级 rich-inline 渲染和诊断

[English](guide.md) | 中文

## 变更

实验性插件为实质性回答提供默认 HTML 创作规则，包括要闻和报告。新结果使用 `rich-html` 围栏 JSON，原有发布工具和标记继续支持。流式预览只读，不执行生成的脚本。结构化 Markdown 长回答显示带标注的兼容阅读，不属于模型创作的交互 HTML。实时格式失败默认至多发起一次已记录的修正请求（`maxFormatRepairAttempts`，0–2）；修正不能执行工具或重复业务操作，查看历史不触发修正。停用插件可保留旧消息展示。台账在 `submit`、`cancel` 之外增加内部 `render` 动作，旧版本不能读取含此动作的记录；新版本可读取已有记录。

桌面原生 `acquire` 请求增加可选 `sdk` 源码，在生成的 JavaScript 之前单独执行。旧容器会拒绝此字段，生成内容没有获得额外能力。

桌面每次页面启动都会通过进程私有 IPC 向 Host 读取当前 Client 插件入口。两个进程一起重建后，替换插件再刷新不会继续加载已移除的旧地址。公共 HTTP 接口和生成内容的桥接能力不变。

## 迁移

1. 升级前备份 profile 的 `rich_inline` 存储文件。如可能降级，应保留此备份。
2. 在修改后的工作区运行 `pnpm run build:lib` 和 `pnpm --filter @deepseek-ai/dsh-desktop run build`。通过桌面插件管理器安装新插件 `.tgz`，保持开关启用，然后用 `pnpm run start:desktop` 重启。
3. 自然要求生成要闻报告或动画。确认生成期间消息内出现只读预览，完成后启用交互。脚本异常应显示可信修复状态并产生新版本，同时保留草稿。新格式无需提示词提醒或额外的渲染工具调用。
4. 完整替换系统提示词的 preset 会收到已记录的运行时格式提醒；普通会话无需改提示词。不希望增加格式修正请求时，将插件的 `maxFormatRepairAttempts` 设为 `0`。模型仍输出 Markdown 时未通过 HTML 验收，兼容视图仅保留回答。
5. 停用时关闭开关。降级时恢复旧桌面和插件版本及升级前台账备份，另行保留新记录副本。不要删除或修改当前记录来满足旧解析器。
