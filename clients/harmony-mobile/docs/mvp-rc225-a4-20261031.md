## 本轮实际边界

新的合并提交模块、适配器及接线摘要与[离线核验](mvp-postclick-offline-20261031.md)一致，但本轮没有产生 `submit-and-observe` 请求。最终桌面提交证据为 `click: not-issued`、观察次数 0，因此不能把本轮称为合并提交路径的真机通过或失败，也不能推断手机握手结果。

第二份准备的正常 Allow 已审查，随后动作预算到期，结果为 `deadline / connect`。之后桌面工具检测到人工输入，停止使用旧控件。恢复现场时已无待回答确认框，桌面仍保留 `route-ready`；通过正常“停止本地连接”后，新观察确认原会话为 `stopped`。

自动收尾两次均保留 `cleanup-unverified`：第一份桌面失败、手机停止；第二份因原手机应用窗口不可见，双端状态为 unknown。原手机进程仍在，正常将原 EntryAbility 带回前台后，PID、UID和窗口均未变；独立停止及最终只读核对确认已配对、未连接、连接按钮禁用。没有强制结束进程、重新配对或清除数据。界面截图抓取失败，没有将其作为 UI 验收证据。

自动失败记录没有改写成成功，独立恢复结果另行保存。已验证的七项主机源码和十四项保护文件指纹不变，包括共享 SDK、生成文件及封存候选；本轮没有改产品源码或重新打包，也没有逐项比较历史数据内容。

## 后续体验与驱动要求

下一轮优先采用用户手动操作手机、主机负责连接准备、计时和恢复的短流程，先完成真实回复和停止体验，减少多轮桌面自动化等待。继续自动验收时，连接阶段必须覆盖正常确认和完整就绪读取；共同可用时间还须包含独立网络 owner 的提前收尾截止，不能仅取授权、路由和中继服务期限。该较早截止没有导致本轮两次失败，但会限制更晚的准备，剩余时间不足时不得追加尝试。

原配对和当前版本继续使用，不据本轮编排失败制作新手机包。回复、停止和三分钟连接必须取得真实证据后，才能把 MVP 标为完成。
