# rc2.19 连接期限与完整候选

rc2.19 将桌面 device、手机和中继的连接期限统一为 10 分钟，解决旧候选在 30 秒房间截止时关闭连接的配置限制。完整候选位于 [MVP 候选 ZIP](../handoff/mvp-rc2.19-20261030.zip)，包含完整未签名手机 HAP、桌面 Harmony 插件 TGZ、中继 ZIP、公开维护工具 ZIP，以及配置调整清单和输入哈希。该归档保留原封存字节；桌面现已加载 rc2.19，手机采用后继 rc2.20，安装和本轮实机限制统一见 [rc2.20 当前状态](route-history-rc2.20.md)。原配对、数据及旧候选保留。

## 期限规则

桌面 `connectionTtlMs` 与 `relay.maxRoomTtlMs`、手机 `relay.maxRoomTtlMs`、中继 `broker.roomTtlMs` 与 `maxRoomTtlMs` 均为 600000 毫秒。签名路由较早到期时，票据和房间仍受该截止时间限制。10 秒挑战、15 秒端点挑战上限、10 秒加密握手、30 秒入房等待及 60 秒空闲回收均保持独立；正常目录轮询为连接提供流量，不绕过空闲回收。到期关闭不隐式取消已接受的任务，也不自动重发请求。

公开维护工具直接从当前桌面 device 示例和手机配置生成 `relay-endpoint-timers.json`，在构建信息中保存输入哈希。它不再复制旧 `.build` 目录中的期限文件；归档时检查这些配置仍匹配构建输入。已有桌面和中继需要同步设置才能接受新房间，单独安装手机无法解决期限冲突。

候选中的 `configuration-changes.json` 列出需审阅合并的字段。[升级说明](upgrade-guide/v0.2.1-rc.2/device-connection-lifetime/guide.zh.md)列出混用旧端点时的拒绝行为。不得将完整示例覆盖到已有配置，也不新建身份或初始化另一份配对日志；原 device 路由日志路径、head、历史和其他设置保留。已授权安装后的桌面期限为 10 分钟，中继两项期限只在本轮有限窗口内调整，结束已恢复原字节；实机尚未取得连续连接证据。

## 离线证据

- 期限与配置 8 项通过：虚拟时间下，同一房间越过 30 秒和 3 分钟，在 10 分钟截止时关闭；更早路由到期、主动取消和迟到计时回调均收尾。另有超过任一端点上限时拒绝提案及存储写入的检查。修复前保留 4 项行为失败记录。
- 配对与票据 19 项、诊断与取消 42 项通过；真实绑定所有者的合成目录在 3 分钟后仍可读取，较短路由截止仍限制票据。
- 桌面控制 5 项、包内反馈 11 项、包内公共 API 冒烟及 1 项本机加密回环通过。加密回环覆盖目录、切换和快照，原生 SDK 使用显式替身，不证明手机实际网络或 UI。
- 定向严格类型检查零诊断，官方 API26 类型检查与完整 HAP 编译通过；编译警告保存在构建日志。73 项原生输入、147 项打包输入及当前共享 SDK 哈希已重新核对。
- 四个主体归档及组合 ZIP 的内容、版本、配置和 CRC／SHA-256 核对通过；rc2.18 手机和 rc2.16 桌面候选哈希保持。

桌面控制首轮在并行构建时出现一次 20 秒超时，单独复跑 5 项通过；未扩大超时。沙箱拒绝本机 TCP 回环及 DevEco 目录链接，分别以 `EACCES` 和 `EPERM` 留下记录；相同命令在宿主权限下通过。首次结果与复跑结果均保留，不将其合并成一次全绿记录。各项报告及输入哈希见[候选证据](../evidence/mvp-candidate-rc2.19-20261030.json)和[组合 ZIP 哈希](../evidence/mvp-candidate-rc2.19-archive-20261030.json)。

## MVP 剩余验收

离线期限测试和本机加密回环属于不同证据，不能合并声称真机持续连接已通过。下一次获准安装和开窗后，先确认三端实际设置匹配，并在提交连接前准备好会话页观察，再验证连续连接 3 分钟、真实目录、专用“MVP体验”会话回复、停止生成和会话往返。当前没有待执行的窗口批准，MVP 真机可用性仍未验收。
