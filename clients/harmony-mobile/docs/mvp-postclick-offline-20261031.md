# 桌面提交后核验离线修复

桌面最终提交和提交后只读核验已合并为一次主机调用，不再等下一轮操作请求读取结果。[最终证据](../evidence/mvp-postclick-offline-20261031-final.json)记录 199 项单元检查和 12 项控制集成检查通过，共 211 项；新提交路径包含 23 项检查，严格模块检查零诊断，七个改动代码文件的正确性 lint 通过。本轮没有访问已安装双端、原配对、HDC 或中继，没有打包、安装或开启实机窗口；最近实机核验组合仍为桌面 rc2.23、手机 rc2.25。

## 一次调用与原期限

[上轮窗口](mvp-rc225-a3-20261031.md)明确记录桌面点击之后的核验回执晚于动作截止约 6.77 秒。修复位于主机操作代码：[`submitDesktopAndObserve`](../operations/desktop-postclick-submission.mjs)在已有正常确认审查之后点击一次，随即激活同一窗口并有界读取当前面板，整个过程在持有官方 Computer Use 客户端的主机调用内完成。后续读取只有只读核验，没有再次点击、自动接受许可或重新连接。

[桌面适配器](../operations/connection-ui-adapters.mjs)要求调用方提供 `submitAndObserve(input, signal)`；缺少该端口会在观察或输入前拒绝构造，没有回退到旧的分离请求。调用方保持原动作截止、取消信号和观察次数，主机执行器在每个异步操作前后检查原截止及本地时钟。首次点击的同步异常仍同步传出，从而阻止另一端继续提交；已经开始的异步调用仍由 owner 等待并收尾。

主机返回 `dsh-desktop-submission/1` JSON，分别携带点击回执、实际面板字段和失败码，不返回截图图像字节。适配器验证该进程回执，并再次核对每个观察的原窗口、profile、Session、当前公开面板和待确认状态；只有点击已确认、当前面板为 `transport-started` 且没有独立失败时，才放行后续消息。布尔成功、空观察、错误会话、错误窗口、超额观察、损坏回执或迟到成功均不能代替这些核验。

## 离线证据

在本目录执行 `node scripts/check-desktop-submission.mjs` 可运行本轮完整检查，入口已包含新模块、新测试及输入摘要。测试使用实际适配器、协调器和消息流程，只替换 UI、时钟、HDC 子进程等外部接口，没有发现应用、读取原身份或连接远程服务。[最终整合记录](../evidence/desktop-submission-offline-1793430306346-5ea4fb30.json)为 211 项通过、失败／跳过／取消均为零，检查期间源码摘要未变。

[旧实现反例](../evidence/mvp-postclick-negative-20261031.json)在隔离副本中保留旧适配器，在相同动作截止下得到 1 项预期失败、0 项通过，无跳过、取消、信号或进程超时，失败为 `action-timeout`。修复后的同一场景只产生一次 `submit-and-observe` 主机请求，并在原截止前完成。该场景证明请求合并及截止行为，不是原机耗时测量。

现有取消、超时、同步失败、错误面板和双端收尾检查继续执行。新检查同时覆盖激活失败、截止前拒绝点击、回读期间到期、时钟回退、非法进程回执，以及取消或超时后迟到的序列化回执；在途调用未结束前不会宣称已经正常停止，不重放点击。首次整合有 198 项单元通过、1 项失败，原因是合成夹具未把慢准备后新建的动作截止传给主机子调用；修正夹具使用同一份已准入截止后全部通过，没有放宽生产期限。[首次失败记录](../evidence/desktop-submission-offline-1793430086811-9293ca03.json)保留。

Node REPL 分别以合成客户端执行新模块和下一轮处理器，均为一次点击、一次核验通过，未使用真实 `sky` 或读取窗口。该结果只确认模块能在对应 JavaScript 运行环境加载并执行，不能证明真实 Electron 捕获或手机连接通过。

## 下一轮接线与验收限制

本地已准备 `.build/postclick-offline-20261031/verification-worker.next.mjs` 和 `desktop-submit-handler.next.mjs`，摘要见最终证据。worker 的最终动作使用 `submit-and-observe` 单请求，并单独保存 `desktop-submission-evidence.json`；主机处理器要求已审查的 Allow、当前按钮和窗口，以及调用前授权检查。两者只能接入新的、已明确批准的运行目录；本轮没有建立新授权或启动 worker。无授权运行模板会在 HDC 和 UI 操作之前拒绝，旧窗口的授权、回执和启动标记不能复用。

十四项保护文件，包括共享 SDK、生成文件和 rc2.24／rc2.25 封存候选，指纹未变；本修复无需重打手机 HAP、桌面插件或中继包。[上轮实机结果](mvp-rc225-a3-20261031.md)仍为零测试消息且已关闭，手机回复、生成中停止和连续连接至少三分钟尚未完成原机验收。下一次沿用现有双端及正常确认流程，使用合并处理器复验，不能把本轮离线通过记为 MVP 已完成。
