# 工作区离线链路测量

本页定义工作区承载的局部诊断，不是 CI 性能门禁，也不代替设备验收。先测量现有实现；本轮不预设压缩、改分块或缓存插件脚本的优化。

| 项目 | 本轮定义 |
| --- | --- |
| 用户操作 | 打开同一标准工作区，确认原生导航交接完成；打开原翻译插件设置，确认表单可编辑；保存 `ja` 并从 Host 回读。 |
| 固定负载 | 390 × 844 页面、两个合成空 Session、同一标准 Web 构建及未经修改的可选翻译包。实际版本、产物 SHA-256 和请求数量随证据保存。没有模型请求。 |
| 实际入口 | 标准 Web 客户端、HAP document-start 脚本、标准 Gateway 与 Client Modules、现有 JSON 分块。ArkWeb 端口和资源加载由 Chromium 测试接口代替。 |
| 时钟 | `performance.now()`；从页面导航开始到导航就绪、到配置可编辑，以及一次保存回读。排除 Host/Profile/浏览器进程启动。没有用户思考时间。 |
| 链路 | 基线不加延时；对照增加 80 ms 往返延时，并将双向 JSON 字节合用一个 1 MiB/s 预算。预算共享、每次传输有取消信号，单独记录请求与响应字节。它不复现真实 TCP、拥塞、丢包或无线电行为。 |
| 冷热状态 | 每次使用独立浏览器页和临时 profile。本轮是无原生缓存的冷工作区；进程内原生壳层缓存另有功能测试，不把浏览器缓存结果当作原生热启动。 |
| 内存 | 不测量或推断原生峰值、持有内存、GC 或温升。容量和队列功能测试只说明配置上限及清理行为。 |
| 输出和停止条件 | 每种条件先保存一个原始诊断样本，记录完成条件和实际字节。不据单样本定阈值或宣称统计提升；成功保存和撤销清理后结束。 |
| 行为证据 | 原插件配置值、Session 权限拒绝、未知写入不重试及撤销后的资源拒绝仍由同一场景核对。 |
| 未包含 | 外层加密/RPC envelope、真实公网中继、原生 UI/ArkWeb、真机内存、弱网恢复、文件上传、模型时延。没有优化或性能阈值，因此本轮没有性能回退负对照。 |

## 原始样本与缓存验证

先保存的[无延时样本](../evidence/workspace-prototype-1793697179191.json)工作区约 2,989 ms 就绪，[80 ms / 1 MiB/s 样本](../evidence/workspace-prototype-1793697212325.json)约 31,463 ms 就绪；后者就绪前生成响应 JSON 17,560,185 字节。两次均不使用原生缓存，启动准备不计入导航计时。

随后增加原生缓存对标准版本化批量脚本的支持。桌面每次提供新鲜授权与 SHA-256 清单，手机核验内容后缓存；相同桌面重新打开仅复用清单仍确认的内容。启动 HTML 与 API 始终实时读取，进程重启清空。容量、错误摘要和变更清理有独立功能检查。

`node scripts/check-workspace.mjs --cache` 在同一 80 ms / 1 MiB/s 条件下执行实际 ETS 缓存，SDK 字节与摘要 API 由替身实现，资源仍由 Chromium 渲染。冷热计时均包含新鲜 bootstrap、摘要清单和页面启动；热样本来自同一进程已使用过的工作区，不包含应用进程重启。每次计数前通知旧文档关闭并排空请求。此口径与前两次样本不同，不作跨口径比较。

| 同轮条件 | 工作区就绪 | 请求数 | 响应 JSON 字节 |
| --- | ---: | ---: | ---: |
| 冷缓存 | 32,550 ms | 302 | 17,681,272 |
| 同进程热缓存 | 2,529 ms | 74 | 257,452 |

[当前源码样本](../evidence/workspace-prototype-1793701524870.json)记录 ETS、生成文档和原包指纹，热打开命中 8 个资源，复用缓存响应 JSON 共 17,394,576 字节，并完成原配置保存与撤销检查。此前的[缓存诊断样本](../evidence/workspace-prototype-1793700312182.json)保留原始结果。两轮均为功能与开销定位，没有重复分布、真实 ArkWeb 峰值内存或无线网络结果，不能据此承诺手机启动时延或统计提升。

## 模拟器键盘与重复打开诊断

[测量卡](../evidence/workspace-keyboard-measurement-card-20261104.json)定义同一合成 Rich 会话的五轮打开／关闭、计时点及应用 PID 内存范围。[实际 ArkWeb 运行](../evidence/workspace-installed-native-rich-1793724307306-probe-i1C0z3.json)使用安装版运行时副本与封存四包，先完成四响应功能验收，再重复打开会话；重复阶段没有额外模型响应。测试页增加键盘窗口观察和计时标签，生产所有者与缓存实现保持原样。

| 轮次 | 原生 ready 回调 | 原生 close 完成 | 关闭后应用 PSS |
| --- | ---: | ---: | ---: |
| 1 | 6,642 ms | 474 ms | 340.0 MiB |
| 2 | 7,114 ms | 464 ms | 379.4 MiB |
| 3 | 6,652 ms | 462 ms | 335.4 MiB |
| 4 | 6,109 ms | 426 ms | 380.5 MiB |
| 5 | 6,702 ms | 483 ms | 427.0 MiB |

原生 ready 从测试页调用 open 计时，包含本地 HTTP 载体与 ArkWeb 启动，不代表首帧或会话已可输入；驱动另外等待真实会话输入框。UITest 观察到可输入的耗时为 7,971–8,943 ms，包含 HDC 命令与布局采样开销，不能直接当作产品时延。close 等待组件分离，五轮均确认 Web 已移除，不声称渲染器 PID 退出。

`hidumper --mem 21690` 只采集独立应用 PID 的 PSS，保留 11 份原始输出，不包含独立渲染进程总量，也未强制 GC。关闭基线为 379,894 KiB，最后为 437,255 KiB，增加 57,361 KiB；中间有回落，五轮不足以确认长期有界或排除泄漏。当前记录是无阈值诊断，后续仍需区分载体与启动成本、延长保留观察并覆盖渲染进程和真机。

[分项复核](../evidence/workspace-memory-components-20261104.json)重新解析同一组原始文件，不是新测量。基线至最后关闭时，ArkTS heap PSS 从 62,139 增至 68,227 KiB（+6,088），native heap 从 122,407 增至 158,588 KiB（+36,181），arkweb-pa heap 从 39,324 增至 52,872 KiB（+13,548）；native heap 的中间关闭样本降至 80,048 KiB。主要增量出现在 native heap，已有回落不能解释其保留原因。下一轮需要关联独立渲染器 PID，并在关闭后增加稳定阶段采样；这些计数尚不足以支持产品优化或内存上限承诺。

## rc2.57 置顶长会话冷启动与重开

在 Mate 90 Pro Max API 26 模拟器，用 rc2.57 工作区源码、最新桌面三包和回环加密连接打开一条合成置顶会话。历史共 80 轮、480 条事件和 400 个压缩帧。测试从新应用进程启动，沿用隔离测试应用原数据目录，未清缓存。原生和标准 Web 均显示同一条会话的合成正文。首次打开和同一应用进程内五次重开全部通过，每次关闭均返回原生历史并移除 Web 组件。[完整采样](../evidence/workspace-pinned-lifecycle-rc257-emulator.json)

应用启动到置顶会话可点击为 3,400 ms，点击会话到原生正文为 7,315 ms，首次点击工作区到标准 Web 正文为 27,201 ms。五次重开为 9,619、9,871、10,843、10,560 和 8,988 ms，中位数为 9,871 ms。六次关闭到原生正文恢复且 Web 移除的中位数为 4,288 ms。各段分别计时，含 HDC 与 UITest 操作开销。当前回环配置使用 512 KiB Host 分块，单次冷进程样本不建立真机或公网时延结论。

应用进程 PSS 从打开前的 271,441 KiB 升到最后关闭并等待 10 秒后的 376,823 KiB，增加 105,382 KiB。六次刚关闭时的样本介于 376,681 和 432,210 KiB，序列有回落。相对基线，等待后的 ArkTS heap、arkweb-pa heap 和 native heap 分别增加 61,942、28,696 和 14,816 KiB。14 份原始样本只计该应用 PID，独立渲染进程尚未归属到样本。当前结果无法判定长期增长或内存上限。

## rc2.57 标准 Web 启动分段

在同一模拟器、同一合成历史和 512 KiB 分块的隔离 Host 上比较首开与同进程重开。桌面使用封存包已有的请求计时。首轮未从环形日志取得原生计时。复验把固定阶段时间放在测试副本的返回按钮测试 ID 中，由 UITest 读回。产品源码和归档不变。[分段原始记录](../evidence/workspace-pinned-startup-stages-rc257-emulator.json)

| 时段或计数 | 首次打开 | 同进程重开 |
| --- | ---: | ---: |
| 原生等待准备工作区 | 492 ms | 701 ms |
| 调用加载到主文档响应 | 276 ms | 318 ms |
| 主文档响应到 ArkWeb 页面结束回调交接端口 | 20,848 ms | 4,798 ms |
| 交接端口到 Web 就绪 | 1,345 ms | 1,470 ms |
| UITest 点击到观察到历史正文 | 28,055 ms | 9,620 ms |
| Host 分块读取请求 | 71 | 37 |
| Host 收到请求到提交回复的时间区间并集 | 1,701 ms | 1,446 ms |

首开与重开相差 18,435 ms，其中约 16 秒的差异出现在主文档响应之后、端口交接之前。桌面区间并集只计已提交回复的请求，覆盖请求处理和提交，不覆盖请求间等待及回复送达。阶段计时把范围缩小到 ArkWeb 加载与端口交接前的资源路径，仍未区分资源往返、设备端解码与页面处理各自的占比。原测试包已恢复，回放和真实模型调用均为零。

### 512 KiB 与 1 MiB 的 Host 分块对照

从封存产品构建核对 rc2.57 的原生上限为 1 MiB。隔离 Host 使用该上限复跑同一合成会话，桌面三包、计时驱动和原生测试逻辑相同。两份测试 HAP 的 86 个编译输入逐字节一致，另两项是临时回环 CA 及其索引。两个分块上限各记录一次首开和一次同进程重开。[分块对照证据](../evidence/workspace-startup-chunk-comparison-rc257-emulator.json)

| 观测值 | 512 KiB 首开 | 1 MiB 首开 | 512 KiB 重开 | 1 MiB 重开 |
| --- | ---: | ---: | ---: | ---: |
| Host 分块读取请求 | 71 | 58 | 37 | 37 |
| 主文档响应至端口交接 | 20,848 ms | 17,491 ms | 4,798 ms | 4,894 ms |
| UITest 点击至观察到正文 | 28,055 ms | 26,205 ms | 9,620 ms | 9,328 ms |

1 MiB 首开少 13 次读取，重开的读取数相同。此轮仍在主文档响应至端口交接前等待约 17.5 秒。每种分块仅有一组样本，计时用于定位，不能据此建立稳定提速幅度。1 MiB 下两次均显示同一会话正文，关闭后返回原生历史，零新增会话、零模型调用，原测试包已恢复。

### 1 MiB 下的原生资源计时

隔离 HAP 在主文档响应到端口交接之间，跟踪同源 GET 资源从缓存查找后到交给 ArkWeb 的时间，排除主文档本身。沿用同一合成历史与桌面三包。每个时段按区间并集计时，资源之间可并发，不同列可能重叠。计时只记录时长和数量。[资源采样](../evidence/workspace-startup-resource-coverage-rc257-emulator.json)

| 观测项 | 首次打开 | 同进程重开 |
| --- | ---: | ---: |
| 主文档响应至端口交接 | 18,177 ms | 4,672 ms |
| 被跟踪资源数／缓存命中数 | 8／0 | 8／8 |
| 至少一个资源在原生处理器中 | 14,949 ms | 844 ms |
| 至少一个资源等待原生并发槽 | 6,524 ms | 0 ms |
| 至少一个资源在加密调用中 | 13,241 ms | 0 ms |
| 缓存校验区间 | 1,156 ms | 0 ms |
| 构造响应和交给 ArkWeb 的区间 | 2,294 ms | 844 ms |
| 最后一个资源交还后至端口交接 | 2,485 ms | 3,213 ms |

首开 18.2 秒中有 13.2 秒至少一条加密资源调用仍在执行。该口径合计请求往返、端侧分块组装和编码，三者尚未单独计时。最后一个资源交还后的等待在重开时更长，首开多出的时间集中在原生资源路径。首开和重开均显示正文并返回原生，零模型调用，原测试包已恢复。

### 四个与八个资源并发槽

沿用 1 MiB 分块、同一合成历史、桌面三包和计时实现。除回环 CA 及其索引外，隔离包只把原生资源槽从四个改为八个。工作区总在途请求预算为 32，标准 Web 端口的预算相应从 28 变为 24。[并发对照证据](../evidence/workspace-startup-slot-comparison-rc257-emulator.json)

| 观测项 | 四槽首开 | 八槽首开 | 四槽重开 | 八槽重开 |
| --- | ---: | ---: | ---: | ---: |
| 至少一个资源等待并发槽 | 6,524 ms | 0 ms | 0 ms | 0 ms |
| 至少一个资源在加密调用中 | 13,241 ms | 14,475 ms | 0 ms | 0 ms |
| 主文档响应至端口交接 | 18,177 ms | 19,340 ms | 4,672 ms | 4,584 ms |
| UITest 点击至观察到正文 | 25,549 ms | 27,324 ms | 9,320 ms | 9,523 ms |

八槽消除了本轮资源排队，首开正文仍稍晚显示。资源排队与其他加密调用在时间上重叠，因此以正文可见时间衡量端到端收益。当前每种设置只有一组样本，产品候选采用四槽。八槽组两次均显示正文，关闭返回原生，零模型调用，原测试包已恢复。

### 缓存校验与 ArkWeb 响应复用解码结果

隔离候选把缓存校验得到的正文交给 ArkWeb 响应复用，沿用原缓存预算和 SHA-256 校验。在 SDK 替身中，同一个可缓存资源首读的解码次数从两次降为一次。新增检查在原实现上按预期失败，候选通过全部 36 项，覆盖空正文和损坏资源拒绝。[SDK 替身对照](../evidence/workspace-decoded-body-substitute-rc257.json)

四槽、1 MiB 分块和同一合成历史下，构造响应及交还 ArkWeb 的首开区间并集从 2,294 ms 变为 1,509 ms，主文档响应至端口交接从 18,177 ms 变为 16,344 ms，正文可见从 25,549 ms 变为 24,395 ms。每种实现各有一组样本，解码次数有对照验证，端到端提速幅度仍需重复测量。该改动留在隔离候选中。两次打开均显示正文并返回原生，模型调用为零，原测试包已恢复。[ArkWeb 对照](../evidence/workspace-decoded-body-experiment-rc257-emulator.json)
