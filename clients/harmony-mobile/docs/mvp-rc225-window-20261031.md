## 窗口与预算

本轮批准为原桌面、原手机及 `dsh.devinho.me` 上的单次最长三十分钟窗口，消息上限为专用“MVP体验”内的两条文本。中继和代理的临时期限修复已应用，独立网络收尾 owner 在修改前就绪。正常面板创建、手机审核签署及桌面确认使用原配对；没有绕过产品确认或复用上一轮批准。

前三份双端签署的本地准备均未上传、未登记、未连接，因准备后余量不足被关闭，原记录分别保存在本轮 `unused-offer-1` 至 `unused-offer-3`。最终第四份路由完成公开字段上传及登记；它是本轮唯一登记的远程路由。

桌面工具的首个索引动作缺少截图几何，补充真实窗口截图后才可执行；UIA 不返回 Allow 的选中状态，因此保留实际截图审核。另一次将 CLI 校验器导入 Node REPL 时触发 `process is not defined`，随后恢复使用既有 CLI 路径。三个等待中的操作驱动在未开始验收时被依次替换，均未提交连接或消息；这些操作准备问题不计为手机产品缺陷。

最终固定预算为连接 30 秒、第一条回复 90 秒、第二条生成与停止 120 秒、独立观察 200 秒及收尾 60 秒，共 500 秒。第三项独立期限采用中继比路由提前十五秒停止的实际值。失败回执时共同可用时间约 486.5 秒，短缺约 13.5 秒，`createMvpWindowBudget` 返回 `insufficient-time`；没有缩短观察、收尾或延长期限，也没有进入消息流程。该差值按失败回执时间推算，不是精确记录的拒绝瞬间。

操作方在异步预算已经拒绝后仍点击了正常“连接”按钮，产生一个尚未提交的产品确认框；该确认随后选择 Deny，未执行双端提交。面板留下相应的命令未完成提示，之后独立新观察确认公开状态为 `stopped`、无待确认请求、无运行中的生成。后续流程必须先取得完整预算准入回执，才可打开连接确认；不能把“启动了检查进程”当成准入成功。

## 独立收尾

网络 owner 在预算拒绝后停止中继、撤销最终路由，并恢复中继配置、代理配置及服务 dropin。独立 SSH 回读确认路由 epoch 2 / revoked / active false，中继 inactive / disabled / MainPID 0，无临时 dropin，代理及中继配置恢复原字节。该网络修改窗口约十七分十二秒，未超出三十分钟批准。

独立手机回读确认 rc2.25、原 UID、已配对、未连接且连接按钮禁用；桌面正常停止后新观察确认 `stopped`、无待确认请求或运行任务。宿主进程核对确认本轮全部驱动退出；窗口授权已标记关闭并保留原批准审计副本，不能复用。既有手机亮屏监督按用户“完成之前别让手机锁屏”的要求保留。

## 后续范围

本轮只确认签署、原位安装、冷启动和恢复收尾，没有验证新关闭顺序在原机暖重连时的表现、手机回复、停止生成或三分钟连接。阻碍首先是准备及操作驱动耗时，不能记为 rc2.25 连接缺陷，也不据此制作新手机版本。

下一次执行应沿用当前双端，先在限时路由创建前完成官方桌面接口、手机公开输入清理和驱动准备；网络及公开回执就绪后立即取得固定预算回执，再进入正常连接确认。共同预算中的连接阶段应覆盖该确认与双端提交，不能在确认准备后再次人为等待。新的实测窗口仍需明确授权，当前不自动重开。
