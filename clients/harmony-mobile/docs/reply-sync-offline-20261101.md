# 回复同步离线修复

本页对应桌面 rc2.23、手机 rc2.26 的[原机 a2 失败](mvp-rc226-a2-20261031.md)后续离线调查。源码已有一处确定修复，原机约 140 秒断连的唯一根因尚未确认；没有签署、安装、修改已安装应用、访问原配对或开启新窗口。既有取消确认时序修复保留，已封存 rc2.26 ZIP 的 SHA-256 仍为 `7a403d817c716e60238d3994587ce2d2cff2030afba656265a278aaa43941a06`。

## 分片容量

[语义模型](../src/semantic-phone.ts)和[快照解析](../src/domain.ts)原先把 `maxBlocks` 同时用于限制内容块数组和流式分片数组。默认 `maxBlocks=256` 时，只有思考、正文两个内容块的回复也会在第 257 个小分片被拒绝，读流变为只读，正文和完成事件不再到达界面。中途接入同一条长分片回复的快照也会被拒绝。[旧实现反例](../evidence/reply-fragments-negative-20261101.json)使用 Git HEAD 的两个源文件在临时目录执行，两个案例均以 `domain-too-large` 失败，没有回退工作区文件。

流式分片改由既有 `maxBytes` 总字节预算约束；单片文本、持久消息的实际内容块数、事件数量、RPC 队列和加密通道容量限制保留。累计字节超限仍在提交状态和游标前拒绝，不提高配置数值，不裁掉历史，不跳过错误帧，也不重发任务。两个原失败案例、累计字节超限、内容块超限及游标不变均有回归覆盖。

[读流核心](../src/phone-core.ts)在终止性读取失败时保持已接收历史为只读，并输出一次 `DSH_PHONE_READ_FAILURE=<固定错误码>`。日志仅输出允许的固定分类，其他错误使用 `follow-failed`；不记录消息、身份、路径、凭据或原始异常。日志输出失败不替换原始读取错误，也不触发任务重试。

## 约 140 秒断连

当前证据能确认语义读取失败不会在 RPC 这一层直接关闭共享通道，因此不能把本次分片缺陷单独认定为原机 Socket 关闭的原因。原机记录只有通用错误 `200` 和随后关闭，缺少当时的分片数量、终止性读取错误、完整关闭信息及中继最后活动时间；尚不能确认分片缺陷就是 a2 的实际触发点。

已核对的期限配置和时间线尚不能确定一个 140 秒的固定连接截止。现有原机记录已排除验收 owner 的收尾截止先触发；当前离线的读流续订和同进程重连也没有复现该断连。32 段读流预算、历史容量限制和原生清理失败仍是独立状态，不能仅凭时长归因，也没有因此改动其上限、中继期限、心跳或代理配置。

[独立 rc2.27 候选](phone-candidate-rc2.27.md)已包含源码修复和固定读流错误码；获准原机复验时持续采集固定分类，核对终止性读取错误是否早于 Socket 关闭，并保留关闭前后的目录活动。安装和复验仍需新授权，旧窗口不可复用。当前不将 MVP 标记为通过。
