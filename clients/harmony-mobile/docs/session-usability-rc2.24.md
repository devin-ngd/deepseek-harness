# rc2.24 手机会话可用性

rc2.24 的原生聊天区域只显示用户和助手消息，语义日志仍完整保留。非用户上下文继续由原有 Session 和模型重建机制持有，不作为助手回复铺满手机聊天区。此处不更改存储、配对、消息发送或富内容授权。

[完整未签名候选](../handoff/mvp-rc2.24-20261031.zip)已封存，包含手机 rc2.24、复用的桌面 rc2.23 和中继/工具 rc2.21；[清单](../evidence/mvp-candidate-rc2.24-20261031.json)及[独立载荷核验](../evidence/mvp-rc224-artifact-smoke-20261031.json)确认 ZIP/HAP CRC、完整原生载荷、复用组件逐字节相同、共享 guest SDK 未变。HAP SHA-256 为 `55df955b1d36cfbb03b64e2c898f89182427fc0ad8337478d484ca4c2c1bd820`。

原生订阅在本地十秒读取期限到达时正常结束该读取分段，再由原有 `PhoneCore` 在有限分段预算内发起新的 `session.sync`。真正的远程错误、畸形内容、请求过期和恢复耗尽仍保持只读拒绝；任务、动作和取消均不自动重发。未增加期限、重试次数或网络权限。

离线反例证明，旧实现将八个安静的本地读取分段算作网络失败，最终产生 `follow-recovery-exhausted`。修复后的真实 RPC / transport / core 组合经过二十个十秒分段仍可写，零任务派发，并完整释放定时器；这项合成证据不能确定上轮手机只读提示的唯一原因。

从本目录运行 `pnpm run test:session-json`，会先严格检查并生成当前源文件，再执行协议、原生文本呈现、订阅恢复、语义、传输和去重回归。65 项通过，真实错误和预算耗尽的拒绝用例保留。官方 API26 完整未签名构建退出 0，保留既有系统能力与异常处理警告；源码默认禁用。手机已完成原材料签署和原位安装，当前实机结果见[rc2.24 复验](mvp-rc224-window-20261031.md)。

71 项消息/UI 离线检查通过，任务状态文案为“已接收，尚未完成”“已完成”“已取消”。单项合成加密回环通过，另外 22 项按过滤未执行；未运行总回归。初次未封存构建及文案补齐时被既有清单拒绝的准备目录均已保留，最终候选从新清单重新构建并核验。

当前安装组合为桌面 rc2.23、手机 rc2.24，原配对、UID 和数据保留。[最近同版本复验](mvp-rc224-repeat-20261031.md)完成两条发送及第一条手机回复，但手机停止前达到截止，收尾从桌面终止任务，本轮三分钟观察未完成。此前[约 184 秒连接](mvp-rc224-window-20261031.md)单独保留，MVP 尚未全部完成。窗口已关闭，中继与代理恢复；[更早记录](mvp-rc223-window-20261031.md)保留其历史范围。
