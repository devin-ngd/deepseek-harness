# 旧进程重连与完整 MVP 预算

本轮修复已建立会话的关闭顺序，并为连接、两条消息、完整三分钟观察和收尾提供统一预算入口。[汇总证据](../evidence/reconnect-budget-offline-20261031.json)记录 239 项定向检查通过、严格类型检查通过及隔离 API26 未签名编译成功。本轮没有签名、安装、访问原配对或打开实机窗口；原机暖重连和手机停止生成仍未完成验收。

## 重连修复

离线用例使用真实 `DeviceProductRpc` 会话视图，替代网络和时钟。[修复前基线](../evidence/phone-diagnostics-1793415569435.json)为 42 项通过、2 项失败，无取消或跳过：`view.close()` 需要通过通道发送取消订阅，但原断开流程并行关闭视图和通道，可能先释放通道，产生清理错误并使同一连接 owner 拒绝后续连接。此前测试夹具自身的取消结果不计为产品缺陷证据。

[最小修复](../src/mobile-device-product.ts)等待已建立会话的消费者关闭，再释放通道；即使消费者关闭失败，也会释放通道并保留失败结果。真实清理失败仍拒绝重连，不清除失败标记、不增加自动重试，也不修改租约。原生端口获取或握手期间仍立即取消，已有取消隔离检查继续通过；尚未完成的会话选择沿用有界 RPC 等待，迟到视图关闭后才释放其通道。

该故障可以离线复现，但不能据此认定它是[上轮旧手机进程连接失败](mvp-rc224-repeat-20261031.md)的唯一原因：现场未捕获精确异常，二十四小时启动租约也不支持早先的租约过期解释。

## 完整窗口预算

[预算器](../operations/mvp-window-budget.mjs)接收授权、路由和中继的实际 epoch 到期时间，取最早者，再保守换算到统一单调时钟。中继若比路由提前十五秒停止，必须传入该中继期限。后续检查同时约束单调时钟和实际到期时间，时钟后退或墙钟跳变不能延长窗口。各阶段截止时间及收尾预留均不可修改，全部阶段必须严格早于最早到期时间结束。

完整入口为 [runBudgetedMvpVerification](../operations/mvp-verified-start.mjs)，当前[准入顺序](mvp-admission-offline-20261031.md)通过 `prepareWindow` 持有窗口准备和预算创建，通过准入后才调用 `prepareConnection` 准备正常确认，再等待双端适配器准备、重新检查预算并传入消息流程。两条消息成功后，唯一手机 UI 操作者串行读取同一连接和会话，从第一份已完成的新采样开始观察至少 180 秒；断连、对象变化、只读状态、过大采样间隔、时钟无进展、取消或到期均不能通过。低层启动函数只核验启动，不能单独作为完整 MVP 验收入口；下一轮驱动应调用工作区完整入口，不直接复用历史脚本或绕过它发送消息。

以下为回归中的显式示例，并非产品默认值，也不保证真实模型在该时间内完成。观察阶段除 180 秒外另留采样余量。

| 阶段 | 示例预留 |
| --- | --- |
| 双端连接 | 30 秒 |
| 第一条消息及回复 | 90 秒 |
| 第二条生成及手机停止 | 120 秒 |
| 独立连续连接观察 | 200 秒，含 180 秒观察及 20 秒余量 |
| 收尾并核验恢复 | 60 秒 |
| 合计 | 500 秒 |

应先准备手机、核对对象及收尾 owner，再创建限时路由；路由和中继就绪后按实际期限固定预算。准备耗时或模型等待不能挤占后续观察及收尾；剩余时间不足时不提交连接，不缩短观察或收尾来凑成功。

完整入口在取消、到期和准备失败后仍等待收尾回调完成。回调负责终止本轮已接受任务、停止并等待适配器、撤销路由及独立核验中继恢复，未核验恢复时必须拒绝；收尾失败和超期分别报告。调用方仍须提前建立独立收尾 owner，最迟在观察阶段截止时开始收尾，并在收尾阶段截止前完成。外部端口必须有界，不能将仍在运行的自定义调用或仅发出停止请求当作收尾完成。

239 项通过包含合成 UI、受控时钟和本地加密连接，不包含真实模型调用；测试中的三分钟由受控时钟推进，不是原机三分钟验收。本地加密载体首次运行受到沙箱 loopback `EACCES` 限制，原命令经宿主重试通过；隔离编译首次受到符号链接 `EPERM` 限制，原命令经宿主重试成功。最终检查未降低断言；编译保留已有异常和 Syscap 警告。

[隔离输入记录](../evidence/reconnect-offline-native-inputs-20261031.json)核验修复源码已进入验证构建。主工程生成文件、共享 SDK 及既有 rc2.24 封存包的七项保护指纹不变。本页记录的 HAP 仅用于完整编译验证，不表示可安装或已通过原机验收；另行构建封存的[rc2.25 完整未签名候选](reconnect-candidate-rc2.25.md)使用相同 JS bundle，仍待获准更新后验证原机暖重连、手机回复和停止，以及同一完整窗口内的三分钟观察与恢复收尾。
