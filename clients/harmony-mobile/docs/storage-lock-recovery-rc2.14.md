# Device storage lock recovery

Device-mode storage uses a stable, non-replaced gate file with the installed SDK File.tryLock(true). A process-local registry also rejects concurrent same-process owners. Close releases the descriptor; actual native crash-release behavior is not yet qualified. Legacy Session storage retains its existing behavior.

The explicit recovery action is pinned to the original binding ID, epoch, phone alias and both public fingerprints. It verifies the original HUKS public identity, binding signature, all route signatures and binding references, duplicate/retirement rules and the latest known terminal-route anchor. An active old window, unfinished pending write, dirty marker, invalid record or ambiguous legacy marker refuses recovery. Records are never replaced with empty state.

After validation under both gates, unchanged record bytes are checked again and empty legacy lock directories are renamed to retained recovered-v1 directories. The record files are not rewritten. Partial archival can be continued only after another complete validation. New writes create a persistent write-unknown marker before changing data; failures keep it and block subsequent reads. No old connection is opened or reactivated. Power-loss and directory durability remain unqualified.

The original phone is installed at rc2.14 with the original certificate and UID. Conditional native recovery verified the original binding/HUKS identity and all four signed/retired routes, then archived both legacy markers without rewriting record bytes. Normal exit and a new process startup reuse the binding directly, disconnected and without another recovery action. Native File.tryLock support and clean-close reacquisition are verified on the target; forced death and power loss remain untested. Desktop and relay are untouched.
