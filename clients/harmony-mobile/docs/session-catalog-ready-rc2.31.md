# 手机会话目录误报

原机 rc2.30 打开“手机MVP体验”后显示 `catalog-unavailable`，同时历史实际可以加载。`PairedProductTransport` 在连接工厂返回之前发布授权成功，页面立即请求目录时连接对象尚未交付，首个读取因此得到 `transport-lost`；后续读取成功也没有清除这次目录错误。rc2.31 将“已连接”的发布放在授权和连接交付都完成之后，保留真实读取失败的提示。

一个针对性回归在旧实现稳定失败，修复后通过，覆盖授权早于及晚于连接交付。现有的一项本地加密集成补充了双会话往返和无目录错误断言，通过；其余 23 项未选择。初次严格检查覆盖 196 模块并通过，官方 API26 编译通过。最后再次运行聚合类型检查时，依赖源码 `rich-inline/src/host/index.ts:173` 和 `test-support/loader-smoke/src/agent-turn.ts:49` 报回调返回类型错误；本轮没有修改这两处，也没有据此声称最新聚合检查通过。

手机已用原签名材料从 rc2.30 原位更新到 rc2.31，UID 20020297、原配对、数据和深色 UI 保留；桌面和中继保持 rc2.30，本轮没有发送消息。原机首次打开及返回后再次打开“手机MVP体验”均加载历史且不再出现顶部误报，结束时保留当前连接。

旧“MVP体验”的往返仍未通过：出现过 `device-catalog-unavailable`、数据通道关闭及 `connection-cleanup-failed`。两份保存历史在本地完整快照投影中均可接纳，不能据此认定原机读取或原桌面订阅收尾正确。75 秒固定字段日志观察已退出，原始日志没有归档；旧会话断连的具体根因尚未确定，未调整中继期限或资源上限。下一步需要桌面对应读取／订阅收尾的阶段证据，再决定修复位置，不继续重复点击。
