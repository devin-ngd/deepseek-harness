# 双端启动与挑战超时

本次仅修改本地执行辅助代码、回归和说明，没有操作已安装应用、原配对、数据或中继，没有重开实机窗口。[上次窗口](rc216-window-20261030.md)仍为握手未通过；本地回归不能补判真实连接成功，也不能认定现场超时的唯一根因。

## 离线结果

[控制集成](../integration/connection-stagger.test.mjs)直接导入当前 `RelayControlClient`、`RoomBroker` 和 `RelayRooms` 源码，复用固定测试密钥、内存端口和实例虚拟时钟。挑战期限保持 10000 毫秒，房间期限保持 30000 毫秒；不使用连接重试控制器。

| 第一个端点 | 第二端点延迟 | 判定 |
|---|---:|---|
| 桌面／手机分别先到 | 0 毫秒 | 双端获得同一轮、同一房间回执 |
| 桌面／手机分别先到 | 9999 毫秒 | 同一房间回执；此例即时验签、投递，不证明真实网络有足够余量 |
| 桌面／手机分别先到 | 10000 毫秒 | 首端挑战到期关闭；后端单独签名不能取得房间 |
| 桌面／手机分别先到 | 21797 毫秒 | 复现错峰不重叠，双端分别超时，无自动重连 |

另检查签名恰在挑战截止后返回时不发送证明、已排队的旧房间回执不能恢复关闭端点，以及剩余端点收到新挑战时中止旧房间。每例收尾等待控制队列完成，核对内存端口监听和过期回调归零。新增协调器接入同一真实控制夹具，证明桌面动作回执尚未释放时，手机动作已经发出且双端取得房间。

## 最终动作协调

[prepareConnectionStart](../operations/prepared-connection-start.mjs)只接受调用方已准备好的两端 `ready` 和 `submit` 回调，构造时不执行 IO。`ready` 是对已审阅当前选择的同步检查；`submit` 必须立即发出正常产品最终动作，返回有界的动作确认，不能把准备、许可、定位或握手观察藏在回调内。资源和取消仍由调用方持有，动作确认也不代表连接或清理完成。

辅助代码在等待任何动作确认前连续调用两端提交，使用同一单调时钟检查最终操作截止与本地调用间隔。调用方显式提供的间隔上限必须严格小于现有挑战期限；测试使用 1000 毫秒。未就绪、取消、过期或无效时钟时拒绝动作；首端调用已耗尽期限、间隔超限或同步抛错时阻止第二端。已发出的动作失败一律报告结果未知，保留调用方正常停止和独立核对责任，不自动重放。一次提交即消费该实例，拒绝后也不能再次使用。

[桌面和手机 UI 适配器](connection-ui-adapters-20261030.md)已接入本协调逻辑并完成离线回归，保留正常产品确认、原对象检查及取消后的独立停止验证。本地调用间隔不等于网络拨号间隔；无法终止的工具调用保持 pending，owner 等待原工作后才停止，不提前报告已清理。尚无本次实现的实机 UI 或连接资格，不能靠延长挑战 TTL、隐藏接口或先报成功绕过核验。

## 后续获批窗口的执行顺序

本节是后续执行要求，不是新窗口授权；旧授权和路由仍不可复用。原[限时范围与收尾要求](rc216-next-window.md)保持。

1. 拨号前完成 route 双签、登记、服务前置检查、采集器与全部停止／撤销／恢复准备，固定唯一尝试及操作和清理截止。
2. 手机原主机许可、连接按钮定位与桌面正常连接确认框均先准备；两端保持当前可见选择。无法预先准备或可靠定位时停止准备，不能先启动一端再处理另一端许可。
3. 现场适配器离线审阅通过后，核对两端就绪、尚有操作及清理余量，再连续发出各一次最终提交。两次提交之间不插入截图、状态轮询、主机许可或等待第一端传输启动。未满足调用预算或结果未知时不补点第二次，转入原收尾。
4. 两端动作均已发出后再等待动作确认、读取固定阶段。分别记录实际拨号时间和挑战／回执阶段；本地动作确认只能证明调用完成，不能证明已经拨号。首次明确失败立即收尾；仅观察截止仍记不确定，不自动重试。
5. 后续成功标准仍为双端就绪、首次目录和连续保持 3 分钟。所有结果均须正常停止、持久撤销并独立重读、恢复原中继状态，保留原绑定与数据。

## 复查入口与证据

在 `clients/harmony-mobile` 执行 `pnpm run test:connection-start`。默认单元回归也会运行新增的[源码子进程检查](../tests/connection-stagger.test.mjs)与[协调回归](../tests/prepared-connection-start.test.mjs)；源码子进程显式使用仓库支持的 `node --import tsx/esm`，不依赖旧构建缓存。外层包装检查不重复计为产品行为用例。

原始错峰定向结果和候选哈希见[离线证据](../evidence/connection-start-offline-20261030.json)，其输入哈希属于适配器加入前；当前验证见[UI 适配器证据](../evidence/connection-ui-adapters-20261030.json)。没有产品协议或候选包字节改动，无需仅为本次操作流程修正重签或重装。真实 UI 提交时差、HUKS、TLS、E2E 和持续连接仍需后续单独验收。
