# rc2.16 单窗口连接结果

本轮未通过握手和连续保持验收。原双端各连接一次，没有重连，手机报告 `control-handshake/timeout`、目录 0；没有提交模型任务、读取会话正文或执行富交互。首次明确失败后停止验证，双端已正常停止，原配对保留，route 已持久撤销并独立重读，中继及配置已恢复。脱敏事实和全部收尾回执见[本轮汇总](../evidence/rc216-window-result-20261030.json)。

用户批准的是[原设备限时范围](rc216-next-window.md)。本轮唯一 route 为 `62e256c8-c70d-4267-bf62-41525354162b`，北京时间 10:20:59 创建、10:50:59 到期，强制收尾点为 10:45:59。服务器恢复于 10:36:02，输入草稿最终核空于 10:40:12；本轮批准已消耗，不延时、不续窗或重开。

## 启动时序干扰

桌面 `transport-started` 的独立观测时间为 10:33:20.033，手机首次拨号为 10:33:41.830，两者至少相隔 21.797 秒；实际桌面启动还早于其观测时刻。原中继只读配置确认 `challengeTtlMs=10000`、`roomTtlMs=30000`。[控制客户端](../src/relay-control-client.ts)在挑战截止前持续等待房间回执，[中继](../standalone-relay/src/room-broker.ts)要求同一轮双端证明均未过期才发回执。

本轮执行在桌面启动后先进行状态回读，再操作手机主机许可和连接，导致双端启动错峰超过挑战有效期。这是验收操作的已知干扰，可能使双端证明不能重叠；由于没有桌面握手阶段，本轮不能证明桌面当时已退出，也不能将其写成唯一故障根因。稳定连接仍未验收，不能用此结果断言 rc2.16 取消修复无效或原配对损坏。

双端错峰和挑战生命周期的[离线验证与启动流程修正](connection-start-offline-20261030.md)已完成，预览、许可和定位要求在最终拨号前准备，两个拨号动作之间不穿插采集。该证据不补判本轮实机根因或通过状态；后续实机试验仍需现场适配器审阅和新的具体窗口授权，不自动重试或延长协议期限。

## 收尾与保留

手机正常停止后仍已配对、未连接，连接按钮禁用；本轮 route 输入、手机消息输入、桌面公开回执输入和消息草稿均核空。桌面依次确认 `stopped / route-required / bound`，没有待答确认。手机 PID 不变，没有安装、重启 App、创建身份或撤销设备绑定。

本轮 route 注册后由独立进程确认有效；失败后停服释放 journal 锁，持久撤销到 route epoch2，再由新进程读回 `revoked=true / active=false / verified=true`。服务最终 `MainPID=0`、`inactive/dead`、`disabled`，原 ExecStart 恢复，`ReadWritePaths` 和 `DropInPaths` 为空，`ProtectHome=read-only`、`ProtectSystem=strict` 保持。46 个既有候选文件、原配置和旧撤销锚点在前置检查通过，未覆盖候选代码或原配置。

所有本轮 reader 退出，手机 UI dump 的临时文件逐次按确切路径移除；原设备绑定、旧历史及本轮撤销记录保留。辅助脚本和公开路由回执位于本地 `.build/rc216-live-20261030-a1/`，不包含私钥或原始日志。旧路由、授权和 claim 未复用。

## 执行限制

桌面曾出现 AX／截图错配及人工输入保护，未从错配画面发送输入。等待用户提供键鼠空闲后恢复；早先按索引点击确认没有产生命令记录，经独立无待处理回读后，按新鲜画面坐标实际提交一次，明确得到 `route-ready`。公开路由文件上传早于该确认的独立回读；登记和中继启动均等待 `route-ready`，没有在确认前建立传输。

首次 SSH 文本传输失败，固定 LF 字节流的同一只读检查通过；所有远程变更脚本在开窗前固定为 LF，5 份 shell 语法检查通过。清空手机临时草稿时，首个本机命令在解析前失败、未触发手机操作，普通空文本输入随后无效果；最终仅在该可见输入框正常全选退格，独立核空。此类操作证据不能记作产品握手失败。
