# rc2.26 停止验收驱动修复

[原机窗口](mvp-rc226-window-20261031.md)已经验证两条消息和约 220 秒连接，但没有点击手机停止。`TaskState` 将语义 `running` 显示为“电脑正在执行”；正文尚未出现时，额外检查非空 `product-live-text` 会持续等待。语义模型的实时正文只汇总 `text-delta` 和最终文本块，不能把正文缺失等同于任务未运行，也尚未证明本轮正文缺失的唯一产品原因。

[消息控制器](../operations/mvp-message-flow.mjs)在第一条新回复完成、第二条发送后，核对任务为 `running` 且草稿为空，即可准备停止；点击前再次核对运行状态、空草稿和当前对象，点击后仍必须等到手机 `cancelled` 回执。任务已结束、手工草稿、未知点击结果或取消回执缺失仍拒绝通过，不重试发送或停止。

控件观察同时接受已拥有的页面 Scroll，以及 rc2.26 的 `product-conversation-controls` 固定底部 Column。底部控件必须完整位于该 Column 和原窗口范围内；缺少视口、重复容器或裁切会在输入前拒绝，不通过滚动历史修复固定控件的位置。原进程、窗口、页面、会话、只读限制及独占动作记账保留。

[离线核验](../evidence/rc226-stop-driver-offline-20261031.json)记录 124 项正式消息回归和 17 项简单文本准备流程检查；[旧实现反例](../evidence/rc226-stop-negative-control-final-20261031.json)在任务已运行但正文为空时返回 `running-generation-not-observed`、未点击停止，新实现则取得一次停止及取消回执。测试使用实例内状态和受控时钟，没有真实设备、模型或网络；原签名手机包、桌面包和共享 SDK 未改，未安装或重开实机窗口。

后续使用已安装桌面 rc2.23 和手机 rc2.26，正常重开手机后核对原配对及空草稿，再在新授权的有限窗口仅对“MVP体验”执行两条文本。手机任务进入 `running` 后即可验证停止，不等待正文到达；连接持续观察和原中继、代理的独立收尾保持。离线取消回执不能替代原手机的实际停止验收。
