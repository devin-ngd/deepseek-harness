## 失败定位

原 `phone-mvp.mjs` 给 `inputText` 的末尾参数额外拼接了一对单引号；现场保存的输入框文本包含这两个实际字符，因此发送前的等值检查失败。新 [HDC 端口](../operations/mvp-message-phone-port.mjs)直接传递参数数组，不拼接命令行或包裹引号。专用验证消息采用无空格的封闭 ASCII 文本，避免远端 shell 和输入法标点参与这两条测试消息；这不限制产品用户的正常中文输入。

原控件查找把不存在、禁用、屏外和裁切合为“找不到可见且启用的控件”，随后从固定屏幕坐标滑动。该操作不确认当前 Scroll 或编辑区域，可能误触键盘；现场后来出现额外的 `）`，但未保存足够的键盘几何证据，不能认定固定滑动是该字符的唯一来源。新流程分别处理这些状态，并在每次滚动后重新核对完整输入。

原准备阶段的消息 claim 早于输入，不表示已点击发送。[新记账器](../operations/mvp-message-journal.mjs)用独占文件区分准备、即将点击且结果可能不明、UI 点击已回执及最终页面验收；不将点击回执称为模型接收。

## 执行约束

[流程控制器](../operations/mvp-message-flow.mjs)导入和构造时没有 IO。调用方提供已核对的原设备引用、进程、窗口、会话 ID、标题、当前语言资源、单调时钟、截止时间和取消信号；它不发现设备、启动 HDC、连接、重连、安装或恢复路由。生产接入必须由唯一 UI 操作者持有当前获准窗口及收尾责任；旧窗口的批准、PID、窗口号、临时脚本和消息 claim 均不能复用。

完整验收使用[启动模块](../operations/mvp-verified-start.mjs)的 `runBudgetedMvpVerification`：调用方提供 `prepareWindow` 和 `prepareConnection`，由入口先等待窗口准备及预算创建，通过准入后才准备正常连接确认，再捕获双端最终动作。不得在入口外另开确认框或仅凭启动标记点击连接；准备耗时会消耗固定阶段预算，预算构造失败也必须等待独立收尾。低层启动函数单独执行不代表完整验收。桌面提交未核验时不会调用消息流程；进入后仅允许显式提供的“连接中”文字有界等待变为“已连接”，不进行 UI 输入。未连接、对象变化、取消或到期直接停止，不自动拨号或重连；选会话后每次观察仍要求已连接。

| 阶段 | 必须满足的条件 | 不满足时 |
|---|---|---|
| 选会话 | 同一原进程和窗口，当前连接，目录行 ID 与标题均匹配 | 停止；不进入其他会话 |
| 输入 | 选中会话非只读，输入框可见且启用，原草稿精确为空 | 停止；不删除或覆盖已有草稿 |
| 文本稳定 | 允许初始空渲染有界等待，随后连续两次新观察精确匹配；完整树和可见树不得矛盾 | 停止；不补字符、不规范化、不自动重输 |
| 发送控件 | 类型正确、唯一、启用且完全位于当前可见 Scroll 内 | 缺失或禁用只等待；屏外或裁切才尝试有界滚动 |
| 滚动 | 当前 Scroll 完全位于原窗口，右侧手势路径不穿过可见编辑框 | 停止；不退回固定屏幕坐标 |
| 最终点击 | 观察仍未过期，独占 issuing 文件写入成功，未取消或到期 | 不点击；已有 issuing 文件阻止重放 |
| 回执不明 | 最终点击调用抛错或失去回执 | 记为 unknown，停止；不重复点击、不发下一条 |

每次观察包含新完整树、新可见树及前后进程核对；外来覆盖层、进程或窗口变化、过期或重复观察均拒绝操作。HDC 临时布局路径按专用前缀、序号和覆盖类型分开，成功或失败均尝试删除本次临时文件。HDC 命令使用现有有界端口，取消后等待子进程关闭；控制器不通过超时竞争提前脱离仍在运行的原调用。

调用方按当前窗口分配单独的记账目录、不可复用的随机 marker 和布局前缀；将已审核预算显式传入 `maxReads`、`maxScrolls`、`maxViewAgeMs`、`deadline`。路由创建前完成手机就绪及驱动准备，发送前核对批准、路由、消息和三分钟观察的共同剩余预算，不足时不发送，不能临场压缩收尾预留补时间。`pause` 必须可取消且实际等待，HDC 端口须有命令超时和输出上限。控制器在各次 await 前后检查截止，但不会中断一个不返回的自定义端口；窗口 owner 仍负责独立收尾。两个独立测试进程争用同一目录时仅一个获得 flow claim；另建测试目录互不影响。

## 两条消息与验收

`mvpMessagePlan(marker)` 生成两条固定用途的纯文本；marker 限 ASCII 字母、数字、下划线和连字符，长度 8–64。以下 `synthetic_run_001` 仅为离线样例，真实获准窗口必须另生成新值。

1. `Please_reply_only_with:MVP_REPLY_synthetic_run_001.No_tools.`：只点击一次发送；手机必须显示当前语言资源中的助手角色，其后消息末尾一行精确为 `MVP_REPLY_synthetic_run_001`，输入框已清空，任务状态已完成，才能继续。助手消息可包含前置思考文字；不得裁剪标点或空格。用户提示中出现 marker、非末行提到 marker 或生成尚未完成，均不能触发第二条发送。
2. `Please_print_integers_1_to_5000_one_per_line.No_tools.I_will_press_stop.`：只点击一次发送；手机任务进入运行中且草稿为空后，重新观察运行状态和控件，再点击一次正常“停止生成”，无需等待正文。随后必须看到取消完成状态；停止按钮启用或点击回执本身均不能代替取消验收。

当前简单文本准备流程将上述两条替换为 `Hello` 和 `Please_write_a_long_story.No_tools.`，以发送前的最新历史为基线核对新回复。它保留相同的动作记账、第二条运行状态、空草稿、取消回执和窗口截止检查，不能与旧流程同时操作设备。

任一步失败均停止，不补发第三条或重试第二条；第二条开始前第一条回复未确认时，第二条不会发送。若生成在停止前已结束，记录该项未通过，不把点击空闲停止按钮算成功。持续连接三分钟和正常窗口收尾继续由连接 owner 独立取证，不能从此两消息流程推导。

## 离线复验

从 `clients/harmony-mobile` 执行：

```sh
node scripts/check-mvp-messages.mjs
```

该入口运行消息准入、消息流程、HDC 参数适配器、独占记账、实际 ETS 条件、产品布局和连接页面测试，生成独立 `.build/mvp-message-*` 日志及 `evidence/mvp-message-offline-*.json`。非零退出、超时、缺少统计、零执行、失败、跳过、取消或列出输入的摘要变化均不记为通过。当前封闭 ASCII 参数、延迟输入、引号及括号漂移、控件状态变化、错误滚动区域、固定底部控件裁切、正文前停止、丢失回执、取消、截止和文件争用均有反例回归。

## 剩余原生验证

合成布局不能证明原手机的输入法提交时序、实际键盘遮挡、Scroll 可见边界或模型遵守提示。正式页面在离线或只读时禁用发送仍是预期行为。本轮不借此绕过这些条件，也不改原未发送草稿。后续获准实测须先重新核对原生布局、当前语言资源和目标会话，再使用本流程；若本次 Scroll 仍覆盖键盘或控件无法安全定位，当轮停止并保留原因，不增加消息或连接次数。

原会话的完整历史可改变按钮位置；消息完成后的布局仍需新观察，不能复用输入前坐标。对话页当前没有独立的选中会话 ID 标记，因此流程依赖准确目录行选择、完成后的标题和返回控件，以及唯一 UI 操作者；它不能保证有人同时切换到同名会话时仍识别正确。下一轮不得并行运行旧 phone reader 的导航或发送分支。原中继已按上轮收尾恢复 60 秒；新的实机授权仍须包含代理超时临时应用和恢复，否则单用此脚本不能保证持续连接。
