# 手机连接取消与重连隔离

## 当前行为

[已建立会话的关闭顺序修复](reconnect-budget-offline-20261031.md)要求会话消费者先于通道关闭，防止取消订阅产生虚假清理失败并阻断同一进程重连；真实清理失败仍保留失败状态。该项已完成离线回归和隔离编译，原机暖重连尚未验收。下文保留原生获取和握手取消的检查范围。

本地断开使当前连接请求失效。公开绑定读取完成后，失效请求在调用原生连接端口前拒绝；已经进入原生获取或握手的请求接收取消信号，断开等待其资源清理完成后才返回。新的连接请求等待这次断开完成，旧请求不改变新连接的页面状态，也不关闭新连接。原身份、绑定和撤销历史不变。

资源等待由 [DeviceBoundMobileProduct](../src/mobile-device-product.ts)的当前连接请求持有，取消信号由 [NativeDeviceProductFacade](../src/native-device-product.ts)传递给正在建立的通道。路由读取后、原生端口返回后和各握手等待后均检查取消；已经返回的原生端口在取消后只释放，不再打开 WSS。原生资源、core 和 RPC 的关闭操作只执行一次，移除取消监听。清理失败时页面显示既有失败状态并拒绝重连。页面、协议、自动重连策略和确认流程未改。

公开绑定读取指 `DeviceBindingClient.load` 的本地公开记录读取、身份比对与验签。原生 SDK 调用若尚未返回，断开继续等待，不把已发出取消信号当作资源释放成功；未验证真机调用返回的最长时间。

## 离线证据

[绑定读取回归](../tests/device-connection-diagnostics.test.mjs)和[原生取消回归](../tests/native-connection-cancellation.test.mjs)用显式 Promise 屏障控制读取、获取、握手和关闭的完成顺序。新增回归覆盖路由读取、迟到端口、等待中的 ticket、WSS open、控制握手、签名控制握手后的 E2E 临时密钥和数据端口获取、终止关闭、清理失败及重连。真实 ETS owner 在固定 SDK 替身下验证迟到 HUKS 返回不创建新密钥或 socket；已关闭 owner 的迟到拨号结果再次释放。

原公开绑定读取修复前为 26 通过、2 失败；本轮原生修复前的 7 项定向场景均失败，原有 28 项通过。最早的测试夹具编码递归、未结算与清理配置错误另行保留，不能计作产品缺陷证据。最终原生取消测试执行真正的共享 core、公开固定密钥和内存签名控制握手；Node 源码测试使用 Node 全局对象，单独导出原生取消 shim 验证其监听释放，官方编译仍注入原生 shim。

| 检查 | 本轮结果 |
|---|---|
| 连接诊断、公开绑定及原生取消回归 | 42/42 通过，其中本轮新增 14 项 |
| 设备绑定、会话切换与富交互作用域 | 15/15 通过 |
| 实际加密回环、动态会话切换与快照读取 | 定向 1/1 通过，同文件其他 22 项未执行 |
| 连接源码严格类型检查 | 0 诊断 |
| 官方 API26 隔离工程 | ArkTS、未签名 HAP 打包和两个 core 的原生 util 导入检查通过 |

逐项命令、失败报告与源码摘要见[原生取消汇总](../evidence/phone-native-cancellation-20261029.json)；[前一轮公开绑定读取记录](../evidence/phone-connect-cancellation-closeout-20261029.json)保留。加密回环首轮失败，最小 TCP 探针确认沙箱回环连接被 EACCES 阻断；宿主用原命令复验通过，未放宽断言或超时。官方编译保留异常处理和设备能力警告，无签名配置。固定密钥、内存控制、回环网络及 SDK 替身通过不证明原生网络、HUKS 或 ArkWeb 行为。

## 构建范围

共享 core 和 rich 文档直接生成到独立工程，并同步该工程的资源摘要；沿用默认禁用配置，仅使用本地测试 bundle 和未签名构建。主工作区现有生成文件保持本轮开始时的字节。当前共享 rich 源码与旧生成文件存在样式及投影路径差异，因此隔离 ProductCore 的重建不被当作可直接部署的单文件补丁；后续手机候选须按最终共享输入完整生成、封存并验证。

编译后检测到共享 `guest-sdk.ts` 及其测试的独立改动；该 SDK 当前摘要与隔离工程输入回执不同，取消修复的两份源码仍匹配编译输入。共享文件未覆盖或回退，HAP 仅对应回执中的输入快照，不声明它包含随后修改的 SDK。

包含最新共享 SDK 与取消修复的完整手机候选现已独立重建、验证和封存，见 [手机 rc2.16](phone-candidate-rc2.16.md)。上段输入差异仅描述前一份编译快照，不适用于新封存候选。

## 剩余验收

此修复证明离线取消流程在等待原生资源、握手和释放期间保持重连隔离，不能认定它解释了曾经的目录后断开或 control-handshake/timeout。手机最后实测版本为 rc2.15，当前运行版本未重新查询；桌面插件实际激活版本和原配对恢复也未在本轮核验。

匹配最终输入的手机候选已经封存；桌面控制面板实际激活版本、未来原位安装兼容性及实机采集清单仍需核对。部署和新实机联调仍需另行明确范围；本轮没有安装、签名、访问原 profile／配对、接触手机或中继，也没有新建连接窗口。[历史现场及清理证据](HANDOFF-2026-10-28.md)继续保留。
