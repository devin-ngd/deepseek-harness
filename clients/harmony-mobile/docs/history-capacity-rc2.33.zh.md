# 手机历史容量

[English](history-capacity-rc2.33.md) | 中文

原机出错会话仍保持连接，报告 `unknown-outcome`。最近 50 条消息的记录本身为 1,194,036 字节，尚不含首帧和载体元数据，已超过旧桌面响应的 1 MiB 限制。只读统计本地 194 份 v4 会话，64 个最近窗口超过 1 MiB、五个超过 2 MiB，最大记录载荷为 3,155,761 字节。这些尺寸不含首帧投影和传输元数据，可以确认容量不匹配，不能证明手机内存或速度。

## 候选限制

| 所属层 | 限制 |
| --- | --- |
| 桌面原生首帧与手机领域数据 | 4 MiB |
| 桌面响应、手机解码包与加密明文 | 5 MiB |
| 原生加密输入 | 5 MiB |
| 双端与中继的加密帧 | 8 MiB |
| 双端输入队列与中继缓冲 | 16 MiB |
| 原生连接累计发送额度 | 64 MiB |
| 首次历史窗口 | 50 条消息、512 条记录 |
| 单段文本或参数字段 | 262,144 个 UTF-16 单元 |

源码手机配置保持禁用。桌面示例是配置模板，不会更新已安装配置。部署时需保留现有主机、身份、配对、路由与其他设置，只将表中容量同步到双端和现有中继配置。仅更新部分层仍会受最小剩余上限限制。

桌面在首帧字节数或记录数超限时，逐步缩小原生分页的消息窗口。每次重新读取前先关闭被拒绝的订阅，保留原生 `hasMore`，不拆分或丢弃所选窗口内的单条记录。单消息窗口仍超限时返回 `history-too-large`，手机提示到电脑查看，允许继续选择其他会话。产品页面尚不提供更早历史翻页。

手机每个跟随队列同时受帧数和解码包字节预算限制。记录数、文本、内容块、请求、到期与帧总数等保护继续有效。对已退役加密绑定取消等待时不再发送取消订阅；原生通道所有者仍等待资源清理，真实的活动发送或资源释放失败仍算失败。这消除了一个可复现的清理误报路径，尚未用候选重新验收原机的清理报错。

## 验证

源码窗口与队列检查、连接诊断和取消清理回归通过。本地加密实际服务回放覆盖约 3 MiB 历史完整读取、超过 4 MiB 历史缩小原生窗口、交付文本顺序和返回其他会话。回放使用合成会话、固定录制与 loopback 套接字。严格源码／集成类型检查和官方 API26 未签名构建通过，构建日志保留 SDK 告警。

后续统一安装桌面 rc2.33 与本机模拟器后，已打开旧“MVP体验”历史及富内容，返回另一会话并完成新消息。模拟器适配器、本机中继与原生候选使用当前共用容量，手机端共用核心和页面原样复制。见[整合验收](../evidence/mobile-coordinated-20261102.json)。真机与公网中继保持原状，原机报错、实机内存峰值、加载耗时与后台恢复仍未验证。当前报告保留于 `evidence/`；此前 `.build/native-controls-device-rc2-33/` 未签名候选早于这次整合的连接修复。
