# rc2.24 同版本复验

本轮沿用桌面 rc2.23、手机 rc2.24，未重装或修改产品代码。原签名、配对、UID `20020297` 和数据保留。仅使用一个获准的十五分钟窗口、同一条十分钟双端签名路由，在“MVP体验”发送两条纯文本，未操作其他会话内容。见[实测汇总](../evidence/mvp-rc224-repeat-20261031.json)。

第一条手机回复已通过修复后的自动验收，随后第二条发送也已回执。第二条在等待手机非空增量输出时达到消息截止，流程返回 `deadline`；手机停止按钮未点击。桌面随后出现第二条的生成输出，收尾通过桌面正常“停止生成”终止本轮任务，并独立确认已无运行中的生成。桌面收尾停止不能替代手机停止验收，MVP 尚未全部完成。

本轮没有完成三分钟连续连接观察：首个旧进程连接失败、重开和协调耗时压缩了同一路由剩余时间，消息流程结束时已到稳定性采样截止，结果为 `stability-deadline`，采样数 0。不能把启动连接成功或零执行当作通过。[上一轮同版本 183,955 毫秒连接证据](mvp-rc224-window-20261031.md)仍有效，但不是本轮结果。主机消息流程摘要仍匹配此前 147 项离线检查，未修改验收条件、重发消息或增加第三条消息。

原手机旧进程在拨号前拒绝，固定字段采集没有记录新的网络阶段，也未发送模型消息。当前窗口内正常重开手机后，新进程使用同一条已签名路由完成握手并执行两条消息。重开是已观察到的缓解，不能据此判定唯一根因。早先“启动租约过期”的解释已撤回：实际候选 `deviceRoutingTtlMs` 为 `86400000`，即二十四小时，原进程在本轮前运行不足一小时；没有取得原异常码，旧进程失败原因仍未知。

路由签名到期时间始终未变。恢复期间，独立收尾预留由一百二十秒依次缩至六十秒和三十秒；这没有延长路由或十五分钟批准，但也没有补足本轮三分钟观察时间。网络 owner 最终按截止自动关闭，独立回读确认路由 epoch 2 / revoked / active false、中继 inactive / disabled / MainPID 0、无临时 dropin，以及中继和代理配置原字节恢复。手机仍已配对、未连接且连接按钮禁用；五个实测驱动及十个固定字段日志 reader 均已退出。手机保活监督按用户要求继续运行。

两处收尾失败单独保留：桌面适配器报告 `failed`，后续独立新观察确认面板 stopped、无待确认请求且模型任务已停止；首次独立远端核验误用了 recovery 驱动目录作为公共路由目录，纠正为实际 a2 路径后只读核验通过。不能把它们写成首次自动收尾全通过。

下一次实测前先完成手机重开、原对象核对、驱动准备和正常确认准备，再创建有限路由；连接前核算路由、批准、消息和稳定观察的共同剩余时间。若不足以覆盖两条消息、完整三分钟观察和收尾，就在发送前结束该轮，不能依靠临场压缩收尾预留补时间。旧进程失败需离线复现或取得固定类别的错误证据后再决定产品修复；当前不按已撤回的租约假设修改应用，不重开新的实机窗口。
