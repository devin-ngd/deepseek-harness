# 显式续接手机公开信任记录

## Change

候选同时读取 `harmony-product-public-trust/1` 与 `/2`。记录过期会阻止自动启用，但保留显式续接所需的数据。新 `/2` 文档包含下一代确认、全部旧记录及回执、原文档摘要、桌面持久撤销纪元和原桌面 P256 签名。本地撤销继续拒绝续接；文件损坏或写入结果未知时继续阻止使用。

桌面初次登记遇到已有授权记录会拒绝。续接必须具有原手机的过期记录、匹配的原身份与完全相同的会话和操作、桌面持久撤销记录、不同的中继配对标识、新手机签名证明，以及新的桌面授权确认。新授权纪元紧随保留的撤销纪元。中继配对使用独立标识和日志，不恢复旧配对或旧授权。`publicTrustMaxBytes` 配置容量，完整历史必须在签发挑战前通过容量检查。

## Migration

保留原应用数据、HUKS 别名、受保护的桌面身份、公开记录、会话和准入历史。先审阅[第69阶段](../../phase69-successor-candidate.md)中的 unsigned 候选、完整文件清单、权限列表和待批准动作。签名、安装、中继修改和新的限时授权分别需要对应批准；准备候选不会激活这些动作。

获批后导出保留的公开文档，在隔离现场 profile 中选择 `renewal.previousPublicPath`，使用新配对标识和新中继日志。双端核对原指纹、准确会话、操作、新纪元和到期时间。通过原生确认保存签名续接文档，再显式连接。过期、撤销或操作失败不会静默重建密钥或清理数据。

`/2` 文件只支持向前读取：旧 `/1` HAP 无法读取。安装前保留原 signed HAP 和未激活中继文件以回退产物。迁移后须先撤销新桌面授权、停止双端传输，保留 `/2` 文件和全部日志，并让旧 HAP 保持断开。不得用 `/1` 覆盖 `/2`、删除历史、降低纪元或恢复原授权。此私有客户端格式不修改已发布 DSH Session 或 SQLite schema。
