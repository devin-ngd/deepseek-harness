# First-use candidate

## Change

The source phone candidate declares ohos.permission.INTERNET; the preceding permission-free HAP cannot use NetworkKit WebSocket connections. Boot remains inert. A native identity-name field and separate confirmation action can initialize an absent HUKS ECE identity while remote connection remains disabled. Actual API20 or later is required; existing aliases and uncertain outcomes are not overwritten or retried automatically. Rich guests receive no signer or private key.

The portable source replay launcher selects only harmony-mobile-replay, isolates home/agents/temp and drops ambient model/auth variables. Its default journey remains synthetic. The first-use.2 field launcher additionally accepts an explicitly selected isolated home and strict field.json, requires local TTY decisions, imports the native public key, signs a bounded offer, commits the original local grant and installs the existing paired providers only after confirmation. Native UI verifies the offer, signs its one enrollment challenge, approves the exact host and resumes only an identical saved public record. Boot remains disabled.

Desktop identities use a new owner payload, harmony-desktop-identity/1, inside the selected credentials provider. That file is plaintext; Windows ACL protection requires separate review. Session, original grant, public trust and SQLite generations are unchanged. Relay public preparation and exclusive initialization are separate local maintenance tools; neither starts a service. Existing journals are never overwritten. The desktop .2 artifact remains unchanged and requires its declared zod 4.4.3 for public types.

## Migration

1. Retain old sealed artifacts. Use the candidate and hashes in the first-use report; run its portable launcher in a separate directory. Confirm four replay calls, one original dispatch, zero real models/uploads and refusal of unsafe mode or missing fixture.
2. Obtain approval before signing, phone installation, real HUKS creation or activation. Bind debug signing to this phone and local.dsh.mobile.offlineproduct; check any existing bundle before replacement. Native HUKS/TLS/ArkWeb and actual device API remain unqualified.
3. Follow [first-use entries and decisions](../../../phase42-first-use-wiring.md). Invoke field-launch.mjs with a new isolated home, use only public exchange files, approve identity storage and the fixed grant locally, and initialize the relay public journal only after operator approval. Verify the strict field guards and complete synthetic journey before activation. Desktop cold restart creates another replay world and needs another local enrollment; it does not restore running tasks. Never treat replay success as real-phone acceptance. Roll back only listed client sources, retaining receipts, revocation data and old artifacts.
