# 统一流程复验：就绪过期

本次获准窗口已关闭，MVP 未通过。统一入口因就绪过期，在双端最终动作前返回 `not-ready`；没有网络拨号、消息输入或发送，手机回复、停止和三分钟连接均未验收。[完整证据](../evidence/mvp-rc221-unified-window-20261030.json)区分正常路由准备、零提交、初始清理失败及独立收尾结果。

## 实测事实

桌面仍为已安装 rc2.19，原手机为 rc2.21、UID 20020297、PID 46498、窗口 609；原配对保留，准备前未连接。本轮未签名、安装或升级，没有修改原 desktop profile。使用的是已完成 138 项离线检查的统一入口与适配器；桌面最终动作仍采用可访问性按钮，不回退到坐标。

临时应用了 nginx 两条 660 秒读取超时及中继 600000 毫秒房间期限。原配对完成本次路由 `6a95f82b-c52e-4f8a-9e07-4eb9d9aa0a5b` 的双签、公开字段上传、登记和服务启动。路由签名截止保持 11:31:06.901 UTC；操作中把本地收尾预留从两分钟改为一分钟，没有延长签名路由或用户 30 分钟上限。

手机驱动在 11:26:57.968 UTC 完成就绪采集，统一入口到 11:28:38.395 UTC 才被调用，两者相隔 100427 毫秒，超过配置的 30000 毫秒就绪期限。准备与启动被拆在不同工具调用中，中间的人工编排等待导致过期；这是操作流程失败，不是已证明的手机或插件故障。桌面和手机最终动作均为 not-issued，消息端口没有被调用，也没有创建消息 journal。

中继运行时长不代表双端已连接。原手机的过滤采集没有连接阶段记录，不能据中继曾运行就声称连接稳定。原消息草稿未打开或替换；只备份并替换了上一已过期的公开路由表单，原配对和持久历史没有清除。

## 收尾与限制

统一入口最初报告两端清理 failed：桌面仍有待答命令，手机导航包装器又把已经选中的“设备”页签禁用状态误判为不可导航，未调用正常本地停止。这两个失败保留在证据中；不能把其进程退出码 0 算成清理成功。

## 后继离线修正

[准备并立即提交入口](../operations/mvp-verified-start.mjs)在同一次调用中等待两端准备、用同步工厂建立新动作截止的协调器，再立即进入统一提交；准备后不再返回模型等待另一轮工具调用。调用方必须提前审查正常许可和最终可访问性按钮，并在工厂返回前保存 owner，供任何失败下的停止及 settled 等待使用。准备失败时，调用方仍负责取消并排空两个适配器。

新增回归复现了准备后等待 100 秒导致零提交，并验证同调用准备／提交不放宽就绪期限、准备失败不创建协调器且保留未结束的回读供 caller 收尾。[最新整合报告](../evidence/desktop-submission-offline-1793360661704-aa49fee2.json)为 129 项离线检查、12 项控制代码内存集成及严格类型检查通过。该修改发生在本次实机收尾后，没有再次实测，不能计为 MVP 成功。

后续须在创建路由前完成全部运行代码与审查准备，最终动作前确认剩余签名路由时间足够覆盖三分钟观察和收尾。已选中的设备页签无需重复导航；未知状态继续拒绝。原窗口、路由和批准已关闭，不可复用；手机、桌面插件和中继产品包无需为此重装。
