## 取消确认时序

[手机核心](../src/phone-core.ts)在发出 `session.cancel` 前记录当前事件位置，取消确认返回后仍允许之后的 `turn/end` 决定最终状态。确认等待期间先到达的 `aborted` 保持“已取消”，先到达的 `completed` 保持“已完成”；请求前的历史终止事件不能充当这次停止的完成证据。取消操作不因断流自动触发，也不重试发送。

[离线证据](../evidence/cancel-ack-offline-20261031.json)保留旧实现的两个失败案例；修复后严格 TypeScript 检查和 42 项语义、读流恢复、投影及 Session JSON 回归通过，相关文件的局部正确性 lint 通过。测试使用实例内的可控 Promise，没有设备、真实网络或模型。该修复没有进入原生生成代码或已封存 rc2.26，也没有签署或安装新包；它不是本轮 `Hello` 同步失败的已证实原因。

下一步先定位会话读流停止更新的触发条件，并离线区分读取已终止、回包未到达及投影未更新。现有证据不足以选择延长超时、增加重试或更改心跳；暂不因此重打包或重开窗口。后续手机更新和原机窗口须另行授权，原会话、配对和数据继续保留。
