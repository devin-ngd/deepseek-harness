# Independent Harmony relay

This user-selected Node relay installs no DSH runtime, Cordis, model provider, SessionController or chat database. Node HTTP and maintained `ws@8.21.3` mount the same RelayRooms and RelayUpgrade used by the optional DSH adapter. The release includes built ESM, unchanged verified official ws files/tarball and a two-entry npm lock. Server npm installation and lifecycle scripts are unnecessary; optional native peers are absent. Node ^22.19 or >=24 is required. Local Windows/Node tests do not establish Linux execution.

## Activation and trust

The unactivated [first-use maintenance tools](FIRST-USE-TOOLS.md) prepare strict public JSON and exclusively initialize the existing public journal/head after an explicit local decision. They start/reload no service and add no HTTP enrollment route. [Complete local first-use wiring](../docs/phase42-first-use-wiring.md) distinguishes implemented code from real trust/unit/broker approval and physical qualification.

Preparation, preview and initialization require the selected endpoints' strict `harmony-relay-endpoint-timers/1` projection. Issuer challenge and room lifetimes must fit both clients before any proposal or trust write; the proposal uses10/30seconds against unchanged15/60second endpoint caps. Pass the successor maintenance tools `--limits relay-endpoint-timers.json`; older argv refuses. [Upgrade guidance](../docs/upgrade-guide/v0.2.1-alpha.2/original-field-interaction/guide.md) covers consumers and the authorization scope for ordinary local confirmations.

Import and `node server.mjs --config config.disabled.json` create no listener, timer or key. Enabled config binds only127.0.0.1; the example leaves the broker disabled and the room map empty, so all joins fail. Plain HTTP returns404, including enrollment/grant/admin paths. nginx exposes only exact data `/harmony/relay/v1` (`dsh-relay-v1`) and control `/harmony/relay/control/v1` (`harmony-relay-control-v1`) upgrades. Host/subprotocol/header/role mismatches, queries and Cookie fail. Origin is denied by default. Explicit nativeOrigin networkkit-v1 permits only the canonical HTTPS Origin for phone requests with the existing custom routing headers; browser fetch metadata remains denied. This changes no broker proof, room capability, pinned E2E or desktop grant requirement. See [offline compatibility evidence and activation limits](../docs/phase68-connection-diagnosis.md). Control also rejects Authorization headers. Rejected upgrade admission sends the same empty403, Connection close and no-store response, then destroys the flushed stream; it echoes no request field, identity, token or room state. TCP capacity and HTTP parser failures retain transport-level rejection; maintained ws may return400 for its own handshake syntax errors. See [upgrade impact](../docs/upgrade-guide/v0.0.0-phase40.1/relay-upgrade-refusal/guide.md).

An explicitly enabled broker accepts only preapproved public pair registrations: pairId, distinct canonical desktop/phone P256 SPKI, routing epoch, expiry and revoked flag. The initial registration requires the existing native fingerprint comparison, desktop scoped grant and corresponding operator approval; server challenges or self-signed keys cannot enroll anyone. Daily connection uses those existing local identity signers, verifies the selected pair/role/epoch/audience/fingerprint, and signs a fresh bounded nonce with the separate `harmony-relay-control/1` domain. Both roles must prove the same fresh round before either receives a short room receipt. No permanent shared token is used. The broker's routing epoch does not grant DSH operations or replace the desktop grant epoch.

Each role receives only its own one-use capability over the future approved TLS transport. Data joins require both roles; endpoints perform the existing pinned ECDSA/ECDH/HKDF/AES-GCM handshake with new agreement keys and nonce counters. Room expiry, data/control loss or a valid replacement role destroys the old room; both roles must freshly sign a new round. Endpoint leases abort on new challenge or expiry even without incoming traffic. A lost control connection requires a new explicit control transport with the same approved identity and fresh challenge. Shared native WS/HUKS and desktop connection owners are wired and tested with synthetic SDK/loopback ports; their production UI/local trust composition, control-loss backoff, actual HUKS/TLS and phone behavior remain unqualified.

Public-only revocation commits use `PublicTrustStore`: a bounded append journal and separate synchronized public digest/generation head. Enabled CLI brokers require explicit `publicTrust` path/maxBytes/maxRecords, reopen before listening, and never recreate missing state or fall back to configured allow entries. Initial public registration is a separate local-owner-only exclusive initialization; no CLI/HTTP enrollment or revoke route exists. Live denial precedes cleanup and commit, concurrent commits serialize, and both files synchronize before acknowledgment. Clean restarts retain tombstones; missing, torn, corrupt, mismatched, locked or unknown-write state refuses startup and preserves its refusal lock. Applicable directory synchronization is mandatory, including the lock. Actual initialization/activation paths still require approval.

The journal fixes audience/pair ids/public keys/expiry and admits only monotonic revocation successors. A separate head detects truncation of one file to a complete old record. Restoring both files from a matching trusted old backup cannot be detected without an independent trusted anchor and must never be treated as ordinary recovery. Unknown writes/failed sync retain the lock; no automatic truncation, repair, overwrite or stale-lock deletion occurs. Windows tests use real temporary file synchronization plus a POSIX directory-sync substitute; Linux filesystem/power-loss acceptance remains outstanding. No message, room, token, grant or private key can enter this store.

## What the server sees

nginx terminates TLS and can see external IP, HTTP/WS headers, public host/path, pair/room/role/capability, timing and lengths. Node sees the proxy's loopback peer plus forwarded metadata. The control broker sees approved long-term public keys/fingerprints, pair id, routing epoch, nonce, proof/signature and both temporary raw room tokens in process memory. RelayRooms stores token digests; the broker/ShortPairingRooms must retain raw role tokens until receipt/lifetime cleanup. These routing fields are not hidden by endpoint E2E.

E2E data hello exposes role/protocol, ephemeral public SPKI and nonce; application frame headers expose binding id, role, sequence and kind. Desktop grant proofs and Session/task/rich HTML/form/draft/action bodies travel inside endpoint encryption. The relay has no private identity or traffic key and does not decrypt or parse binary bodies. It cannot itself enforce that authorized binary bytes are ciphertext; endpoint pinning and correct crypto are required. Custom E2E and native integration still need qualification.

The application writes no messages, rooms, headers, raw frames, disk queue or chat history. CLI reads static JSON and approved public trust files, and reports only `relay failed` on failure. Public pin/epoch/tombstone/digest/lock files persist once explicitly initialized. JS GC does not guarantee memory byte erasure. TLS keys/certificates require future approval and persistence. Existing nginx/journal/audit/debug settings, swap, crash dumps and VM capture may persist metadata or memory; proposed log/swap/core restrictions have not been applied or verified.

## Deployment and rollback

Each candidate upload/start, DNS/nginx/TLS or identity change requires its corresponding approval. The server currently runs the approved `0.0.0-phase40.1` with an empty room map and disabled broker; this HTTP refusal candidate remains local. Directory `/home/devin/harmony-relay`, service `harmony-relay.service` (User=devin, Restart=no), loopback17846 and nginx TLS are recorded in [actual deployment](../docs/relay-deployment-20261014.md). Preserve existing sites/services and never read/copy their private keys. CLI SIGINT/SIGTERM deny first and wait for owned TCP/WS/timer cleanup; cleanup errors stay visible. Restart loses rooms and all ephemeral capabilities. Cursor/command/action ids belong to desktop/client journals; the relay neither executes nor deduplicates tasks.

Before authorized deployment, record collisions and backups for only the new directory/service/nginx files. Rollback stops harmony-relay, reverts only its approved nginx additions after `nginx -t`, and preserves public revocations, existing sites and predecessor archives. DNS/certificate deletion and pairing-key revocation are separate actions. [Current wiring evidence and remaining acceptance](../docs/phase40-product-wiring.md) distinguish synthetic source-profile/ETS, built ESM and API26 compilation from Linux, TLS, native and phone execution. This package is not recommended for production activation.
