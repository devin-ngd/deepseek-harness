# Local Harmony emulator debugging

English | [中文](README.zh.md)

The configured Mate90 Pro Max emulator uses an independent `dsh-emulator` HUKS pairing with the installed `desktop` profile. Its native UI and `ProductCore.js` are copied byte-for-byte from the common mobile sources and build. Emulator-specific changes are the local relay address and application-private CA loading. Shared fixes enter future phone builds through the same source; this task does not update the physical phone. The installed HAP and signing differ. The desktop adapter builds the common device sources with isolated service and credential names; it does not extract internals from an older installed bundle. [Initial verification](../evidence/emulator-communication-20261102.json) records the original two-way message results and failures.

With the installed desktop and emulator running, execute from `clients/harmony-mobile`:

```powershell
python emulator-dev/resume.py
```

This restores the exact HDC reverse mapping from emulator `127.0.0.1:5555` port `18081` to host loopback port `17847`, starts the local desktop listener when needed and opens the emulator app if stopped. It reuses pairing and sends no model messages. Its success means preparation completed; check the app for the actual connection state. The original phone pairing and desktop configuration rows remain intact. Credentials, TLS key, generated bundles and validation files stay in `.build/emulator-link`.

The common product configuration uses `continuous` foreground follow: clean read segments do not exhaust a total segment budget, while eight consecutive transport failures still stop the reader. Bounded and single-read policies remain available to finite fixtures. A fresh channel reopens the last selected Session when it is still visible; only history and follow reads resume, and messages or other mutations are never replayed. Draft ownership remains attached to its Session during reconnect. Native socket cleanup recognizes confirmed closure and rejected HTTP upgrades before open; unconfirmed release failures still block reuse. [Stability verification](../evidence/emulator-stability-20261102.json) records the actual duration, session creation, message and recovery results. Do not close the app with an unsent draft or active task. Background execution and full rich-content interaction require their own verification.

`prepare.mjs` builds the local adapter from current sources and prepares a fresh native project from `.build/native-controls-device-rc2-32`; `--desktop-only` rebuilds only the adapter. `build-native.mjs` runs the existing shared product builder and copies its core, page and rich-content assets into the existing emulator candidate. The desktop adapter, local relay and native candidate read capacities from `product.config.json`, retaining the emulator identity, CA, room lifetime and frame-count settings. Compile that candidate with `node scripts/build-native.mjs --project=.build/native-controls-emulator-local`, then use `python emulator-dev/control.py install` for an in-place emulator update. `install-desktop.py` is the completed one-time setup and refuses an existing installation; routine debugging uses `resume.py`. Desktop adapter updates require reloading its Host; closing only the window may retain the old Host. `control.py` targets only the emulator and provides observed-layout actions and explicit validation operations.

[Coordinated acceptance](../evidence/mobile-coordinated-20261102.json) records installation of desktop rc2.33, the 4 MiB history budget and common stability fixes. Old large history and rich-content display, returning to a test Session to send a message, native cancellation and natural renewal were exercised; cancellation confirmation with the real model can still take tens of seconds. The persistent desktop input panel is removed, and the settings entry passed the full Web-shell scenario; clicking through the installed Windows settings page remains unverified. Emulator results do not replace physical-phone memory, latency, background or hardware acceptance.
